# xgalaga-hyperspace-web

Web port of [xgalaga-hyperspace](http://runway.org/~mrogre/) 2.1.1.0, compiled
to WebAssembly with Emscripten.  The game runs at 60 Hz (the original is a
30 fps X11 game), with homerow keyboard shortcuts and a shared high-score
leaderboard.

## Building and serving

```sh
cd xgalaga-2.1.1.0
sh web/build.sh          # needs emsdk on $HOME/emsdk and python3
python3 -m http.server 8080 --directory web
# open http://localhost:8080/
```

`build.sh` produces a single self-contained `web/xgalaga.js` (wasm + level
data + sound inlined) served alongside `web/index.html`.

## Controls

- `k` keyboard / `m` mouse / `q` quit (title screen)
- `j` / `l` (or ← / →): move
- `f` (or space): fire
- `d`: shield (when you have one)
- `p` pause, `b` toggle buffering, `s` toggle sound

## Differences from upstream 2.1.1.0

### Gameplay: per-level MINTORPS floors

Upstream, deaths and lemons drive your torpedoes back down to `MINTORPS`
(3 single / 4 double / ...), so by levels 60-90 you are dodging 300+
enemy torps with 3 shots.  This build raises the floor every 15 levels
(the level cycle repeats after 15), via `weapon_mintorps(weapon, level)`
in `data.c`:

| weapon  | 1-15 | 16-30 | 31-45 | 46-60 | 61-75 |
|---------|------|-------|-------|-------|-------|
| SINGLE  | 3    | 5     | 7     | 9     | 11    |
| DOUBLE  | 4    | 6     | 8     | 10    | 12    |
| TRIPLE  | 6    | 9     | 12    | 15    | 15    |
| SPREAD  | 5    | 7     | 9     | 11    | 13    |
| MACHINE | 3    | 5     | 7     | 9     | 11    |

(capped at `MAXTORPS`, raised 10 → 15 to fit).  The floor is applied at
game start, on death, on lemon, and when picking up a weapon
(`prize.c`).  Difficulty still ramps through the enemies; this only stops
firepower from collapsing.  More late-game tuning ideas are documented in
[GAMEPLAY_IDEAS.md](GAMEPLAY_IDEAS.md).

### 60 Hz conversion

Durations are doubled and per-frame speeds halved so gameplay timing
matches the 30 fps original.  Level-8-type "slither" entry paths use
`enter_speed()` in `main.c`, which reproduces the original's 30 Hz
*integer* arithmetic (`m + metaLevel*m/2`, truncating division) and then
halves the result per tick — a plain float halving made odd-component
directions 25% too fast and visibly widened the slither.

### Rendering

- The "LEVEL N" level-intro text uses the same font the original X server
  loads for `W_BigFont` (XLFD `-adobe-helvetica-bold-r-normal--34-*`,
  Nimbus Sans Bold here): bitmap glyphs generated by `web/mkbigfont.py`
  into `web/bigfontdata.h`, drawn with proportional pen advances.
- A 1 px grey (`#808080`) border frames the game canvas so its edges are
  visible against the black page.

### Input

Browsers stop delivering `keyup` once the page loses focus, which left the
C-side key state (`static keys` in `do_player`) holding a movement key —
the rare "J gets stuck" drift.  `web/webglue.js` now synthesizes releases
for the game-control keys (ctrl-b, ctrl-f, space, `x`) on `blur` and
`visibilitychange`, and `do_player` resets `keys` when a new game starts
so a key released during the game-over screen can't leak into the next
game.

## Files

- `xgalaga-2.1.1.0/` — upstream sources (C), modified as above
- `xgalaga-2.1.1.0/web/` — Emscripten backends: `wlib_web.c` (canvas
  windowing), `sound_web.c` (Web Audio), `frate_web.c` (frame pacing),
  `joystick_web.c` (no-op), `leaderboard_web.c` (score bridge),
  `webglue.js` (input + audio glue), `build.sh`
- `web/` — see `xgalaga-2.1.1.0/web/` (the built `xgalaga.js` lives there)
- `leaderboard.py` — shared high-score server (see repo docs)
